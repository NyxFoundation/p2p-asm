# RV64IM SHA-2 compression tests

The pure specification and typed RV64IM implementation are independent descriptions.
These tests compare actual lowered instructions, generated bytes, memory and registers.

## Entry points and ABI

Import `Libp2pAsm.Asm.Crypto.SHA256` or `Libp2pAsm.Asm.Crypto.SHA512`.
`Libp2pAsm.Asm.Crypto.SHA256.compress` and
`Libp2pAsm.Asm.Crypto.SHA512.compress` are `Rv64.SAsm.Stmt` values. Shared code
is in `Asm/Crypto/Sha2.lean`, importing `Asm.Basic.sequence` directly.

| Register / region | SHA-256 | SHA-512 |
|---|---|---|
| `a0`, writable chaining state | 8 LE64 slots, 64 bytes | 8 LE64 slots, 64 bytes |
| `a1`, readable input | 64 bytes, any byte alignment | 128 bytes, any byte alignment |
| `a2`, writable schedule | 64 LE64 slots, 512 bytes | 80 LE64 slots, 640 bytes |
| `a3`, immutable constants | 64 zero-extended LE64 slots, 512 bytes | 80 LE64 slots, 640 bytes |
| stack | 64 owned writable bytes below `sp` | same |

State, schedule, and constants must be 8-byte aligned; incoming `sp` must be
16-byte aligned. All regions are disjoint, nonwrapping, valid, and disjoint
from executable code. The return address must be aligned for the model's
4-byte instruction subset. Lengths and permissions are caller preconditions;
this leaf routine does not validate arbitrary pointers. The constants table
must equal `Spec.Crypto.SHA256/512.roundConstants`, serialized in LE64 slots.

SHA-256 accepts arbitrary high halves in initial state slots, ignores those
halves, and writes canonical zero-extended results. Every SHA-256 addition and
rotation is masked explicitly; the machine model's ADD is 64-bit. Input words
are decoded big-endian with LBU, allowing unaligned input.

Success returns `a0 = 0`. `ra`, `sp`, `gp`, `tp`, and all twelve s-registers are
preserved. Working words use s0..s7; each is saved, restored, and its stack slot
zeroed. The full 64-byte frame, exact schedule payload, and all other
caller-saved registers (t0..t6, a0..a7) are zero on return. Output state remains.
Input, constants, and surrounding guard regions remain unchanged.

All compression instructions are current typed `Instr` constructors, lowered
from SAsm. There are no foreign calls, crypto instructions, custom opcodes,
or raw-assembly implementation. The only assembly written directly is the
test harness. Public fixed loops decode 16 words, expand 48/64 words, execute
64/80 rounds, and wipe 64/80 schedule slots. Eight state loads/feed-forward
stores and the 4/8 byte loads per word are statically unrolled.

## Reproduce

From the repository root:

```sh
python3 Tests/AsmCrypto/check.py
```

Optional arguments: `--prefix riscv64-unknown-elf-` and `--qemu PATH`.
The default QEMU is `qemu-riscv64`; `QEMU_RISCV64` also overrides it.
GNU as/ld/objcopy must be on PATH. The script builds probe dependencies with Lake
and writes generated artifacts under the ignored `build/native/sha2/`.
Python uses only its standard library.

After the complete test command creates fixtures, the standalone model probe
can also be run through Lake:

```sh
lake env lean --run Tests/AsmCrypto/Probe.lean sha256 build/native/sha2/sha256
lake env lean --run Tests/AsmCrypto/Probe.lean sha512 build/native/sha2/sha512
```

## Tested results and artifacts

| Measurement | SHA-256 | SHA-512 |
|---|---:|---:|
| Typed static instructions | 230 | 197 |
| Encoded routine bytes | 920 | 788 |
| Executed instructions per tested block | 6,479 | 6,822 |
| Model cases | 85 | 63 |
| QEMU cases, GNU assembly emission | 85 | 63 |
| QEMU cases, direct encodeProgram bytes | 85 | 63 |
| Independently padded hashlib messages | 17 | 17 |

These counts are measurements for the supplied fixtures, not universal cost or
constant-time theorems. The interpreter runs the actual lowered program with
`runUntil`, checks the return, and verifies that one instruction less exhausts
the execution budget. Both SAsm layout/range validation and encoding succeed.

Each algorithm tests 24 deterministic pseudorandom arbitrary 64-bit initial
states/blocks, four zero/ones/high-bit edge cases, and padded-message blocks.
Messages cover empty input, `a`, `abc`, lengths 55/56/63/64/65,
111/112/127/128/129, 255/256/257, and 1024 bytes. Python independently pads
messages and computes the per-block chaining fixtures; every block is checked
against pure Lean `compress` and an independent Python integer compression.
The final chains are checked with Python hashlib. Full hashes/padding are
test wrappers, not production entry points.

The model checks all 32 architectural register values, every byte in all five
regions, scratch and stack wipes, and exact output/canaries. All eight input
alignments are exercised. Additional diagnostic executions compare the full
PC/access-kind/width/address trace among fixtures with equal public alignment,
and reject accesses outside payloads, including guard reads. This is finite
trace testing, not a universal noninterference result.

QEMU executes both GNU-assembled `Codegen.assembly` output and the binary
returned by `encodeProgram`. GNU objcopy's extracted `.text.protocol` must
equal the encoder byte-for-byte for both ELFs. The harness snapshots all
registers before clobbering syscall registers and then emits all five regions;
the complete output must match the independently checked model snapshot.
Input/constants are mapped in read-only ELF segments.

Per-algorithm artifacts include `protocol.S`, `encoded.bin`, `constants.bin`,
`cases.bin`, `case-N.before.bin`, `case-N.after.bin`, both
`case-N.{protocol,encoded}.native.bin` snapshots, eight `alignment-N.trace.txt`
files, and `measurements.txt`. The last case's harness/ELFs remain for inspection.
Constant bytes are produced from Lean's fixed vectors; Python separately parses
those vectors and checks both `constants.bin` and the exact table bytes passed
to every model/native execution. Snapshot layout is 32 LE64 registers followed
by state, input, constants, scratch, and stack regions, including their guards.

## Proof scope and remaining obligations

`Refinement/Crypto/Words.lean` proves 14 universal identities: low32 projection,
modular addition, choose, majority, 32/64-bit rotation, and all eight SHA sigma
expressions. They use kernel-checked BitVec lemmas, Boolean cases, and `decide`;
no `sorry`, added axiom, or native proof evaluation is used. `ProofAudit.lean`
reports dependencies, and the runner rejects axioms outside `propext`,
`Classical.choice`, and `Quot.sound`, recording `build/native/sha2/proof-audit.txt`.

These identities do not yet prove instruction-sequence or round refinement.
Outstanding: register-level correspondence; decode/schedule/round loop
invariants; whole-function refinement against pure `compress`; universal
termination, memory safety, ABI preservation and zeroization; flattened
fetch/branch correspondence; encoding/native execution correspondence; and
relational constant-time/control/address independence for all valid inputs.
Microarchitectural timing is outside the current model. This is executable,
tested compression with supporting algebraic lemmas, not completed M2.

The production code generator exports `sha256-compress` and `sha512-compress`.
They are block-compression entry points, not whole-message hashes or a network stack.
